# v0.3.0

本版本新增媒体输入、本地 shell 适配和缓存提示保留，并修复跨协议推理历史回传。要求 Go **1.26.7+**，生产与测试代码仍仅依赖标准库。

## 新增能力

- **媒体输入**（[#1](https://github.com/dillonzq/api-translator/pull/1)）：在 Chat Completions、Responses 与 Messages 之间映射可表示的文件输入；音频和视频输入支持 Chat Completions ↔ Responses，保留混合内容顺序。转入 Messages 时仅支持可表示的 PDF、UTF-8 纯文本和 URL 文档；不支持的类型与引用明确报错。
- **本地 shell**（[#2](https://github.com/dillonzq/api-translator/pull/2)）：将 Responses 本地 shell 声明、选择、历史调用及结果适配为函数工具，普通与流式 Responses 输出通过同一份 `RequestState` 恢复完整 shell 调用与稳定 item ID。原生 Responses 上游通过 `NormalizeResponsesRequest` 显式启用。支持省略或空数组形式的 skills；不执行命令。
- **缓存提示**（[#3](https://github.com/dillonzq/api-translator/pull/3)）：Chat Completions / Responses → Messages 保留消息、内容块和工具上的 `cache_control`，包括 TTL 与扩展字段；已有块级提示优先，不自动添加缓存断点。无法表示的提示通过损耗策略报告。

## 修复与维护

- **推理历史回传**（[#7](https://github.com/dillonzq/api-translator/pull/7)）：跨协议请求保留可读原始 reasoning，并与 assistant 正文、并行工具调用及轮次关联。合成的 Responses 普通响应、`response.output_item.done` 和终止 `response.output` 保留 `reasoning_text`，供下一次请求回传。展示 summary 保留，相同 summary/content 不重复输出；请求回传不再用 summary 替代原文。
- **流式错误与状态**（[#4](https://github.com/dillonzq/api-translator/pull/4)）：保留同一次 `Feed` / `Finish` 调用在错误前已生成的事件，首次错误后停止正常输出。按职责拆分 adapter、共享协议类型和状态，统一工具身份去重、碰撞、事务回滚及诊断规则。
- **畸形 JSON**（[#5](https://github.com/dillonzq/api-translator/pull/5)）：避免解码形状不匹配时用零值重建并丢失上游字段；加强工具参数、搜索、引用及错误信封校验与数值精度处理。
- **发布验证**（[#5](https://github.com/dillonzq/api-translator/pull/5)）：统一 Makefile 与 CI，增加竞态与随机顺序测试、覆盖率、流式 fuzz、漏洞扫描、macOS / Windows 验证及稳定的 `CI passed` 检查。发布标签需通过版本和 main 归属校验，再运行完整 CI 后发布 GitHub Release。

## 升级注意事项

这是包含转换输出变化的次版本升级。调用方如依赖精确 JSON 或 SSE 输出，应复核以下行为：

- Responses reasoning 项现在包含可回传的原始 `content`；调用方需保留这些项，避免再次丢弃 reasoning。无法恢复历史中已经缺失的原文。
- 只有 summary、加密/不透明 reasoning、未知推理格式和缺失签名会产生语义损耗诊断；`LossPolicySafe` / `LossPolicyStrict` 拒绝对应请求。
- Chat / Responses → Messages 默认省略无签名 thinking，包括 nil 和零值状态。仅当上游明确支持时设置 `state.Options.AllowUnsignedThinking = true`；Safe/Strict 仍拒绝签名损失。同协议请求保留原字段。
- 本地 shell 只覆盖受支持的本地配置；托管 shell 仅保留在原生 Responses 路径，旧版 `local_shell` 不在映射范围内。Responses 工具恢复必须沿用请求的 `RequestState`。
- 媒体、缓存提示和 shell 的具体方向与限制见[协议转换说明](../protocol-conversion.zh-CN.md)。新增严格校验可能使过去被静默丢弃或错误重建的数据返回错误或损耗诊断。
